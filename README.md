# 옆구기 · 옆동네 구경가기

17개 장르, 92개 세부 분류로 한국 계정 790여 개를 모아 보는 페이지입니다. 왼쪽에서 장르를 고르면 위에 세부 분류 칩이 나옵니다(예: 개그 → 스케치·콩트 / 몰카·리액션 / 캐릭터·상황극 / 틱톡·밈 / 개그맨 채널 / 코미디 쇼·토크 / 더빙·애니, 드라마 → 로맨스·로판 / 사극·판타지·스릴러 / AI 드라마 / 학원·청춘 / 공감·상황극 / 웹드라마 제작 / 숏드라마 플랫폼 / 방송·OTT 공식 / 리뷰·요약). 전체 분류 체계는 `index.html` 맨 위 `TAX`에 있습니다.
프로필 사진·구독자 수·조회수·최근 영상·라이브 여부는 깃허브 Actions가 20분~4시간마다 유튜브 API로 받아 `live.json`에 저장하고, 페이지는 그 파일만 읽습니다(7번 설정 필요). 인스타·틱톡은 같은 카드에 링크로 묶입니다.

## 파일
- `index.html` — 페이지 전체 (수정할 일 거의 없음)
- `data.js` — 계정 목록(한 줄에 계정 하나). 계정 추가·수정은 이 파일만 고치면 됩니다. `cat`이 장르, `sub`가 세부 분류이며 값은 `index.html`의 `TAX`에 있는 것만 씁니다.
- `config.js` — (선택) 브라우저에서 직접 API를 부를 때만 쓰는 키와 설정. 7번 자동 갱신을 켜면 필요 없습니다.
- `.github/workflows/refresh.yml`, `scripts/refresh.mjs` — 자동 갱신 작업. `live.json`(채널 데이터), `ids.json`(찾은 채널 ID)을 만듭니다.

## 1. 유튜브 API 키 발급 (무료, 약 10분)
> 7번 자동 갱신을 쓸 거면 이 단계는 건너뛰고 7-1의 서버용 키만 만들면 됩니다. 아래는 브라우저가 직접 API를 부르는 임시 방식용입니다.

1. https://console.cloud.google.com 접속 → 구글 계정 로그인
2. 상단 프로젝트 선택 → "새 프로젝트" → 이름 아무거나 → 만들기
3. 왼쪽 메뉴 "API 및 서비스" → "라이브러리" → `YouTube Data API v3` 검색 → "사용"
4. "API 및 서비스" → "사용자 인증 정보" → "+ 사용자 인증 정보 만들기" → "API 키"
5. 만들어진 키 옆 연필(수정) 클릭:
   - 애플리케이션 제한사항: **웹사이트** 선택 → 항목 추가에 `https://아이디.github.io/*` 입력 (아래 2단계에서 정해지는 주소)
   - API 제한사항: **키 제한** → `YouTube Data API v3`만 체크
   - 저장
6. 키(`AIza...`)를 복사해서 `config.js`의 `window.YT_API_KEY = ""` 따옴표 안에 붙여넣기

깃허브에 올리면 키가 공개되지만, 5번의 웹사이트 제한을 걸어두면 다른 사이트에서는 못 씁니다.

## 2. GitHub Pages에 올리기
1. https://github.com 가입 → 오른쪽 위 "+" → "New repository"
2. Repository name: `sns-hub` (아무거나 가능) → Public → "Create repository"
3. "uploading an existing file" 링크 클릭 → `index.html`, `data.js`, `config.js`, `README.md` 4개를 끌어다 놓기 → "Commit changes"
4. 저장소 상단 "Settings" → 왼쪽 "Pages" → Branch를 `main`, 폴더 `/ (root)` 로 선택 → Save
5. 1~2분 뒤 `https://아이디.github.io/sns-hub/` 에서 열립니다. (이 주소를 1-5번 키 제한에 넣으세요: `https://아이디.github.io/*`)

## 3. 사용법
- 왼쪽 목록: 전체 / 즐겨찾기 / 장르 17개(모바일에선 가로 스크롤 줄). 숫자는 지금 켜진 플랫폼 필터·검색어를 반영한 개수입니다.
- 장르를 고르면 위에 세부 분류 칩이 나오고, 주소는 `#game-lol`처럼 세부 분류까지 기억합니다. 계정 추가·수정 폼에도 세부 분류 칸이 있습니다.
- 카드는 바뀐 것만 다시 그리고(사진 다시 안 받음), 받아온 데이터는 1초 모아서 한 번에 저장합니다.
- 정렬: 구독자순 / 채널 조회순 / 최근 업로드순 / 이름순. 라이브 중인 채널은 항상 맨 앞.
- 카드 안 영상 순서: 최신순 또는 조회순(최근 10개 안에서). 썸네일에 조회수가 표시됩니다.
- 전체 탭은 60개씩 보여주고 스크롤하면 이어서 불러옵니다.
- 주소 뒤에 `#game`처럼 붙이면 그 탭으로 바로 열립니다.
- 페이지 상단에 "라이브 확인 HH:MM · 전체 갱신 HH:MM"이 보이면 자동 갱신 데이터를 읽는 중입니다. 10분마다 다시 읽고, 바뀐 카드만 다시 그립니다.
- 아이디가 없는 채널은 자동 갱신 작업의 search_count로 찾습니다(7-5번). 잘못 잡힌 채널은 카드의 ✎로 `@핸들`이나 채널 ID를 직접 넣으면 그 값이 우선합니다. 단, 이렇게 고친 채널의 프사·영상은 "data.js로 내보내기" → 저장소 반영 → 다음 갱신 때부터 보입니다.
- `live.json`이 없을 때(설정 전)는 예전 방식으로, `config.js`에 키가 있으면 브라우저가 직접 API를 부릅니다. 이때는 "채널 자동 찾기" 버튼이 나타납니다.
- 카드의 "+ 인스타", "+ 틱톡"을 누르면 그 계정의 인스타·틱톡 아이디를 넣을 수 있습니다.
- 페이지 안에서 수정한 내용은 그 브라우저에만 저장됩니다. 영구 반영하려면 맨 아래 "data.js로 내보내기" → 받은 파일을 깃허브 저장소의 `data.js`에 덮어쓰기(업로드)하세요.

## 4. API 할당량
- 하루 10,000 단위(무료)는 **API 키 하나당**이라 방문자 전체가 나눠 씁니다. 그래서 7번처럼 깃허브 Actions가 대신 받아 `live.json`에 저장하고, 페이지는 그 파일만 읽습니다. 방문자가 몇 명이든 사용량은 고정입니다.
- 비용: 채널 정보 50개당 1단위, 최근 영상 채널당 1단위, 조회수·라이브 영상 50개당 1단위, 채널명 검색 100단위.
- 기본 일정: 전체 갱신 4시간마다(채널 790개 기준 약 930단위), 라이브 확인 20분마다(약 32단위) → 하루 약 7,700단위. 남는 약 2,000단위는 아이디 미확인 채널 찾기에 씁니다.
- 할당량은 한국시간 오후 4~5시쯤 초기화됩니다. 페이지 위 "오늘 API 사용"은 `live.json`에 기록된 실제 합계입니다.

## 5. 법적 준수 (YouTube API 정책)
YouTube API를 쓰는 사이트는 다음을 지켜야 합니다. 페이지에 이미 반영돼 있고, 로고 파일만 직접 넣으면 됩니다.
- **출처 로고**: https://developers.google.com/youtube/terms/branding-guidelines 에서 공식 로고를 내려받아 저장소에 `yt-logo.png`(가로형 로고)와 `yt-icon.png`(정사각 아이콘) 이름으로 올리세요. 파일이 없으면 "YouTube" 글자로 대신 표시됩니다. 로고는 색을 바꾸거나 자르면 안 됩니다.
- **약관·개인정보 안내**: 페이지 하단 "이용 안내 · 개인정보 · 출처"에 YouTube 서비스 약관 링크, Google 개인정보처리방침 링크, 저장하는 데이터 설명이 들어 있습니다. 내용을 바꾸더라도 이 세 가지는 남겨두세요.
- **데이터 보관 30일 제한**: 자동 갱신은 4시간마다 전체를 새로 받고, 브라우저 직접 방식도 30일을 넘지 않게 코드에서 막아 뒀습니다. data.js에서 뺀 채널은 다음 갱신 때 `live.json`에서도 지워집니다.
- **광고 금지**: YouTube 데이터가 표시되는 화면에 광고·후원 배너를 붙이면 정책 위반입니다. 수익화하려면 별도 검토가 필요합니다.
- **사이트 이름**에 YouTube·YT 같은 단어를 넣으면 안 됩니다.

## 7. 자동 갱신 설정 (깃허브 Actions) — 10분
한 번만 해두면 20분마다 깃허브가 알아서 유튜브 데이터를 받아 `live.json`에 넣습니다. 페이지는 API 키 없이 그 파일만 읽습니다.
1. **서버용 API 키 만들기**: 구글 클라우드 → 사용자 인증 정보 → API 키 만들기 → 수정에서 "애플리케이션 제한사항: 없음", "API 제한사항: YouTube Data API v3만" 으로 저장. (웹사이트 제한을 건 기존 키는 서버에서 안 되므로 새로 만들어야 합니다.)
2. **비밀값 등록**: 깃허브 저장소 → Settings → Secrets and variables → Actions → New repository secret → Name `YT_API_KEY`, Secret에 1번 키 붙여넣기.
3. **파일 두 개 올리기**: 저장소 → Add file → Create new file → 파일 이름 칸에 `.github/workflows/refresh.yml` 입력(슬래시를 치면 폴더가 생깁니다) → 내용 붙여넣기 → Commit. 같은 방법으로 `scripts/refresh.mjs`.
4. **첫 실행**: 저장소 상단 Actions 탭 → 왼쪽 refresh → Run workflow → mode `full`, search_count `80` → Run. 1~2분 뒤 `live.json`, `ids.json`이 저장소에 생기고 페이지 상단에 "라이브 확인 HH:MM · 전체 갱신 HH:MM"이 뜹니다.
5. **아이디 미확인 채널 채우기**: search_count 80은 8,000단위라 하루 한 번만 가능합니다. 며칠간 매일 한 번 Run workflow(search_count 80)를 누르면 460개가 다 채워집니다. 다 찾은 뒤에는 "data.js로 내보내기"로 ID를 data.js에 박아두면 더 안정적입니다.
6. **기존 키 정리**: `config.js`의 `YT_API_KEY`는 비워도 됩니다(페이지가 더 이상 쓰지 않음). 구글 클라우드에서 그 키를 삭제하면 공개 노출도 사라집니다.

문제 확인: Actions 탭에서 실패한 실행(빨간 표시)을 열면 로그가 보입니다. 키가 잘못되면 "keyInvalid", API를 안 켰으면 "accessNotConfigured"로 실패합니다. 할당량 소진(quotaExceeded)은 실패로 표시하지 않고 다음 날 자동 재개합니다.
주의: 깃허브는 저장소에 60일간 아무 활동이 없으면 예약 실행을 멈춥니다. 멈추면 Actions 탭에서 다시 켜면 됩니다. 만약 `live.json`은 갱신되는데 사이트에 반영이 안 되면 Settings → Pages의 Source가 `main` 브랜치인지 확인하세요.

## 8. 한계
- 인스타그램·틱톡은 공개 API가 없어서 팔로워 수·최신 게시물은 못 가져옵니다. 링크만 연결됩니다.
- 조사 시점 수치(`followers`)는 API 연결 전이나 비공개 채널에서만 표시됩니다.
